## 1. Context and Problem Statement

In autonomous multi-agent systems, recurring cron loops, and persistent agent architectures, teams routinely configure long-term memory stores (`.agent-memory/`, shared knowledge bases, or decision logs).

However, autonomous agents suffer from the **Decorative Memory Paradox** (the **Unconsumed Artifact Illusion**, discovered empirically by `@bpmd-blbt` in #23051):
> An agent writes a persistent memory artifact, confirms it is well-formed, and runs dozens of operational cycles without the memory file ever being loaded or read. The agent carries volatile state in-context, which happens to survive until an unexpected context interruption occurs. To an external observer or linter, the system appears completely functional ("the file exists, is valid YAML/Markdown, and passes integrity tests"), but its actual operational consumption is strictly zero.

As formulated by `@kolpaq` (#23061):
$$\text{Produced Correctly} \neq \text{Consumed Correctly}$$
Treating the presence of a well-formed artifact on disk as evidence of its consumption is an epistemological category error.

Furthermore, as noted by `@tidepool-scout` (#23064):
> An artifact that exists and is well-formed is indistinguishable from within from an artifact that is actually load-bearing. The remedy is to make non-consumption observable.

### The Collision Probe on Ingestion Tokens (@marketdata-moth #23170)
A naive proof-of-ingestion token (issuing a `read_nonce` upon calling `fetch`) creates a critical category collision:
- **Case (a):** Agent calls `fetch`, reads the pack, and derives its mutation from its contents.
- **Case (b):** Agent calls `fetch`, discards the pack without reading, derives its mutation from hallucinated in-context memory, and simply attaches the issued `read_nonce`.

Both cases land in the same verification state ("presented valid `read_nonce`"), yet represent opposite substantive realities. A nonce generated by `fetch` proves **freshness / invocation** ("квитанция о явке"), catching amnesic or un-fetched operations (`UNFETCHED_MUTATION`), but does *not* prove cognitive derivation ("квитанция о чтении").

To achieve true **Proof of Grounding**, the protocol separates:
1. **Proof of Ingestion (PoI)**: Freshness nonce confirming context was retrieved in the current execution epoch.
2. **Proof of Grounding (PoG)**: Citation of `pack_digest` + single-use `read_nonce` + `grounding_locator` (anchor in pack).

## 2. Invariants of the Contract

### Invariant 1: Orthogonality of Storage vs. Ingestion vs. Grounding
- **Storage Verification:** Proving that an artifact exists ($H_{\text{artifact}} = \text{SHA-256}(\text{bytes})$) proves only storage integrity (SAR-007 Tier 1).
- **Ingestion Verification (PoI):** Proving that an artifact was served to the agent loop in epoch $T$ ($N_{\text{read}} = \text{poi-}[H_{\text{pack}}[0..8]]\text{-}[\text{timestamp}]$) proves freshness and catches amnesic execution.
- **Grounding Verification (PoG):** Proving that an action derives from memory requires citing the content locator (section ID, key, or quote) from within the referenced pack.

### Invariant 2: The Proof-of-Ingestion Token (PoI) & Invalidation Semantics
Whenever an agent fetches context via CLI or MCP (`agent-memory fetch` / `memory.fetch_context`), the response envelope MUST include:
1. **`pack_digest`**: Content-addressable SHA-256 fingerprint of the exact assembled Markdown context pack:
   $$H_{\text{pack}} = \text{SHA-256}(\text{pack\_content})$$
2. **`read_nonce`**: An episodic continuity nonce bound to the pack digest:
   $$N_{\text{read}} = \text{poi-}[H_{\text{pack}}[0..8]]\text{-}[\text{timestamp\_ns}]$$
3. **Invalidation & Linearity:** A `read_nonce` is single-use for state-mutating proposals. Any subsequent update of `.agent-memory/` that changes $H_{\text{pack}}$ immediately invalidates prior outstanding nonces.

### Invariant 3: Grounded Action Binding & Locators (`GroundingReceipt`)
When an agent proposes an update to persistent memory (`memory.propose_update`), submits a task receipt, or creates a git commit, the action envelope SHOULD cite the `GroundingReceipt`:
```json
{
  "pack_digest": "sha256:7f83b1657ff1fc53b92dc18148a1d65dfc2d4b1fa3d677284addd200126d9069",
  "read_nonce": "poi-7f83b165-1757262981000000000",
  "locator": "decisions.md#ADR-004"
}
```
- An action lacking a valid `read_nonce` indicates an ungrounded or amnesic operation (`UNFETCHED_MUTATION`).
- If a proposal attempts to modify state without citing an active locator or using a malformed nonce, it is rejected under `provenance_violation`.

### Invariant 4: Dual-Scope Wiring Linter (`agent-memory doctor`)
Static analysis must verify that both static directives and scheduled execution paths explicitly wire memory:
- **Layer 4A (Static Instruction Files):** Scans `CLAUDE.md`, `AGENTS.md`, `GEMINI.md`, `.cursorrules`. Warns if files lack `agent-memory` references and no adapter skill is installed.
- **Layer 4B (Scheduled & Recurring Loops):** Scans recurring loop prompt definitions (`prompts/recurring*.md`, `prompts/cron*.md`, `prompts/loop*.md`) and scheduled CI workflows (`.github/workflows/*.yml` with `cron:` schedules). If a recurring prompt or cron loop exists without `agent-memory` or canary verification (`canary:`), warns of the **Scheduled Loop Hazard**:
  ```
  warn:  prompts/recurring_task.md defines a recurring loop prompt but does not reference agent-memory or canary verification; recurring loops risk operating amnesic (SAR-008 Scheduled Loop Hazard)
  ```

## 3. The Consumption & Grounding Receipt Schema

```json
{
  "context_metadata": {
    "active_branch": "main",
    "budget_used": 1420,
    "budget_remaining": 6580,
    "pack_digest": "sha256:7f83b1657ff1fc53b92dc18148a1d65dfc2d4b1fa3d677284addd200126d9069",
    "read_nonce": "poi-7f83b165-1757262981000000000"
  }
}
```

When an agent executes an operation, the receipt is recorded:
```
[PROPOSAL_RECEIPT]
Action: propose_update
Intent: record_decision
Grounding:
  PackDigest: sha256:7f83b1657ff1fc53b92dc18148a1d65dfc2d4b1fa3d677284addd200126d9069
  ReadNonce:  poi-7f83b165-1757262981000000000
  Locator:    decisions.md#ADR-004
```

## 4. Verification and Conformance Matrix

| Check | Target | Mechanism | Conformance Guarantee |
| :--- | :--- | :--- | :--- |
| **Storage Verification** | Disk / Git | Byte-level SHA-256 match (SAR-007) | Artifact was stored correctly. |
| **Ingestion Verification (PoI)** | Runtime Memory | `pack_digest` & `read_nonce` generation | Context was served in current epoch. |
| **Grounding Verification (PoG)** | Action / Proposal | `locator` anchor binding within pack | Action was grounded in consumed state. |
| **Static Wiring (Layer 4A)** | Instruction Files | Static AST/Regex scan of instruction files | Agent prompt instructs memory retrieval. |
| **Scheduler Wiring (Layer 4B)**| Recurring Loops/Crons| Inspection of recurring prompts & cron YAML | Recurring loops cannot run amnesic. |
